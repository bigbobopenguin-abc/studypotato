Topic 2Text Pre-processing and Tokenisation

In plain English

Before a computer can work with text, we clean it and chop it into small pieces called tokens.

Remember
  • Tokenisation splits text into tokens; all unique tokens = the vocabulary
  • Word tokens can't handle OOV (unseen) words
  • Character tokens: tiny vocabulary, but very long sequences
  • Subword tokens (BPE) handle new words with a small vocabulary
  • BPE repeatedly merges the most frequent adjacent pair
  • Stop-word removal deletes common words (the, is, and)
  • Stemming removes affixes (prefixes and suffixes) by rule to get the stem, which may not be a real word: flies → fli
  • Lemmatisation returns the lemma (dictionary base form) using vocabulary and grammar, always a real word: flies → fly
Think of it as
Like prepping vegetables before cooking: wash (remove noise), peel (stop words), and cut into pieces (tokens). How small you cut them is the tokenisation choice.
In the test
  • Compare word, character, subword and sentence tokenisation
  • Run BPE merges by hand
  • Tell stemming from lemmatisation from an example
  • Pre-processing = cleaning messy text before a model uses it.
  • Tokenisation = splitting text into pieces called tokens. All unique tokens make up the vocabulary.

Byte Pair Encoding (BPE)

The subword method used by Transformers.

  1. Split every word into single characters.
  2. Start the vocabulary with those characters.
  3. Find the most frequent adjacent pair.
  4. Merge it into a new token and add it to the vocabulary.
  5. Repeat 3–4 until the vocabulary reaches the target size.

Memory hook

Stemming is a rough haircut; lemmatisation is a proper barber. If the result isn't a dictionary word, it was stemming.

Topic 3Part-of-Speech Tagging and HMM

In plain English

POS tagging labels each word as noun, verb and so on. An HMM picks the labels by asking two questions: how likely is this word for this tag, and how likely is this tag to follow the last one?

Remember
  • POS tagging assigns a grammatical category (noun, verb…) to each word
  • It resolves ambiguity: book (noun) vs book (verb)
  • Emission = P(word | tag) = count(word as tag) ÷ count(tag)
  • Transition = P(tag₂ | tag₁) = count(tag₁ → tag₂) ÷ all transitions out of tag₁
  • Path score = multiply all transitions and emissions, <S> to <E>; the highest wins
  • Statistical (HMM) is simple; neural (RNN, LSTM, Transformer) understands context better
Think of it as
Guessing someone's mood from their words. Each word gives a clue (emission), and moods tend to follow each other in patterns (transition). You multiply the clues to score each guess.
In the test
  • Build emission and transition tables from a small corpus
  • Multiply along a tag path to score it (no formula given!)
  • Explain why one zero makes the whole path 0
  • POS tagging labels every word with its grammatical role (noun, verb, adjective…).
  • It resolves ambiguity: "book" can be a noun or a verb; "Washington" can be a person or a place.
  • NLTK tags to know: DT determiner (the, a) · JJ adjective · NN noun · VB verb · MD modal (can, will).
  • Approaches: statistical (Hidden Markov Model: simple, no deep meaning) and neural (RNN, LSTM, Transformer: better context).

Hidden Markov Model (no equation given in the test)

Emission probability
P(word | tag) = count(word with tag) ÷ count(tag)

How likely a tag "emits" this word. Divide by the total for the tag (column total), not the word.

Transition probability
P(tag₂ | tag₁) = count(tag₁ → tag₂) ÷ count(all transitions out of tag₁)

Add <S> at the start and <E> at the end of every sentence before counting pairs.

Score of one tagging
P = Π P(tagᵢ | tagᵢ₋₁) × P(wordᵢ | tagᵢ) (including <S> → first and last → <E>)

Multiply every transition and emission along the path. Highest score wins. Any zero makes the whole path 0.

Topic 5Word Semantics and Text Vectorisation

In plain English

Computers only understand numbers, so every word must become a list of numbers (a vector). Simple methods count words; modern ones learn vectors where similar words end up close together.

Remember
  • Text vectorisation converts text into numerical vectors
  • One-hot: a single 1 at the word's index, the rest 0
  • Bag of Words: word counts, word order ignored
  • One-hot and BoW: sparse, no meaning, can't handle OOV
  • Embeddings are short, dense and learned; similar words have similar vectors
  • Skip-gram: positive = real neighbours, negative = random words; P(+) = σ(w·c)
  • Small window → syntactic similarity; large window → topical similarity
Think of it as
One-hot is like giving every word its own locker number: unique but meaningless. Embeddings are like a map: words with similar meaning live in the same neighbourhood.
In the test
  • List the 3 problems of one-hot and bag of words
  • Explain positive vs negative samples in skip-gram
  • Compute P(+) = σ(w·c)
TermMeaningExample

Text vectorisation = turning text into numbers. From simplest to most advanced: One-hot → Bag of Words → TDM/TTM → TF-IDF/PPMI → Word2Vec/GloVe/FastText.

One-hot encoding

Each word = a vector of 0s with a single 1 at its own index. Vocabulary [cat, dog, fish]: dog = [0, 1, 0].

Bag of Words

Each sentence = word counts; order ignored. "dog bites dog" over [bites, cat, dog] = [1, 0, 2].

3 problems with one-hot and BoW
  1. Sparse and high-dimensional: long vectors, mostly zeros, waste memory.
  2. No meaning: "cat" and "kitten" look unrelated (their dot product is 0).
  3. Can't handle OOV words.

Word embeddings: Word2Vec (skip-gram with negative sampling)

  • Embeddings are short, dense, learned vectors with almost no zeros.
  • Positive samples: real (target, neighbour) pairs from a window. "…a tablespoon of apricot jam, a pinch…" gives (apricot, tablespoon), (apricot, of), (apricot, jam), (apricot, a).
  • Negative samples: target paired with random words, e.g. (apricot, aardvark); several per positive pair.
  • Train a binary classifier to tell real from fake; the learned weights become the word vectors.
  • Every word has two vectors: one as target (W) and one as context (C). Start random; SGD pulls real neighbours together and pushes fake ones apart.
Skip-gram probability
P(+ | w, c) = σ(w·c) = 1 / (1 + e^(−w·c)) P(− | w, c) = 1 − σ(w·c) = 1 / (1 + e^(w·c))
Worked example
w = [1, 2], c = [0.5, 1] → w·c = 0.5 + 2 = 2.5 P(+) = 1/(1 + e^−2.5) = 0.924 P(−) = 1 − 0.924 = 0.076
  • Window size (1–10 each side): small window → syntactic similarity (same part of speech); large window → topical similarity.
  • Analogies: king − man + woman ≈ queen, Paris − France + Italy ≈ Rome.
  • Evaluation: extrinsic (performance on real NLP tasks) and intrinsic (compare with human similarity ratings, e.g. WordSim-353: 353 pairs rated 0–10; (plane, car) = 5.77).
  • GloVe: vectors from global co-occurrence statistics, no labelled data. FastText: Facebook AI library for embeddings and text classification (uses subwords, so it handles OOV words).

Topic 6Term-Document and Term-Term Matrices

In plain English

Count how often words appear in documents (TDM) or near each other (TTM), then compare the rows. Cosine similarity measures how alike two count lists are, ignoring how big they are.

Remember
  • TDM: rows = terms, columns = documents (column = document vector)
  • TTM: |V| × |V| co-occurrence counts within a window (about ±4 words)
  • The dot product favours frequent words; cosine normalises by vector length
  • cos = v·w ÷ (|v| × |w|): 1 = very similar, 0 = unrelated
Think of it as
Two shopping lists: one family buys 2 apples and 1 bread, another buys 20 apples and 10 bread. Different sizes, same taste. Cosine says they're identical (1.0).
In the test
  • Read a document or word vector off a TDM
  • Compute a dot product, vector lengths and cosine

Topic 7TF-IDF and PPMI

In plain English

Raw counts make boring words like “the” look important. TF-IDF rewards words that are common in one document but rare elsewhere. PPMI rewards word pairs that appear together more than chance.

Remember
  • TF-IDF weights a TDM; PPMI weights a TTM
  • TF = log₁₀(count + 1); IDF = log₁₀(N ÷ df)
  • A word in every document has IDF = 0
  • PPMI = max(log₂[P(w,c) ÷ (P(w)P(c))], 0): negatives become 0
  • Centroid = average of the word vectors in a document
Think of it as
TF-IDF: “Romeo” in a Shakespeare play is a giveaway clue; “sweet” is everywhere, so it tells you nothing. PPMI: “peanut butter” and “jelly” show up together far more than luck would explain.
In the test
  • Compute TF, IDF and TF-IDF (log₁₀)
  • Compute PPMI (log₂) and turn negatives into 0
  • Say which goes with TDM and which with TTM

Raw counts overrate frequent but uninformative words ("the", "good"). Both methods re-weight counts.

Used withAsks
TF-IDFTDM (words × documents)Is this word frequent here but rare elsewhere?
PPMITTM (words × words)Do these two words co-occur more than chance?

TF-IDF

Formulas (log base 10)
TF = log₁₀(count + 1)
IDF = log₁₀(N / df) N = total documents, df = documents containing the word
TF-IDF = TF × IDF

A word in every document has IDF = log₁₀(1) = 0, so it gets weight 0. "Romeo" (1 play) has a high IDF; "sweet" (most plays) a low one.

Worked example · "battle" in As You Like It
count = 1, appears in 21 of 37 plays TF = log₁₀(1 + 1) = 0.301 IDF = log₁₀(37/21) = log₁₀(1.762) = 0.246 TF-IDF = 0.301 × 0.246 = 0.074

PPMI

Formula (log base 2)
PMI(w, c) = log₂ [ P(w, c) / (P(w) P(c)) ] PPMI = max(PMI, 0)
P(w, c) = f(w,c) / N P(w) = row total / N P(c) = column total / N

Numerator = how often they actually co-occur; denominator = how often by chance if independent. Negative values become 0 (the "positive" in PPMI), because negative PMI is unreliable on small counts.

Worked example · PPMI(information, data)
P(information, data) = 3982 / 11716 = 0.3399 P(information) = 0.6575 P(data) = 0.4842 PPMI = log₂(0.3399 / (0.6575 × 0.4842)) = log₂(0.3399 / 0.3184) = log₂(1.0677) = 0.0944
Centroid (document vector)
d = (w₁ + w₂ + … + wₖ) / k

Average of the document's word vectors. Example: [1, 3] and [3, 5] → [2, 4].

Topic 8Naive Bayes

In plain English

Naive Bayes guesses a category by asking: for each class, how often did each word appear in training? Multiply those chances with how common the class is, and pick the bigger score.

Remember
  • Naive Bayes is a probabilistic classifier based on Bayes' theorem
  • Naive assumption: words are independent of each other (given the class)
  • Bag of words: word order ignored, only frequency counts
  • Prior = documents in class ÷ total documents
  • Laplace (add-1) smoothing: (count + 1) ÷ (words in class + vocabulary size), so no zero probabilities
  • Ignore P(text): it's the same for every class
  • Precision = TP ÷ (TP + FP); recall = TP ÷ (TP + FN)
Think of it as
A detective with a tally sheet: “disappointed” was mostly in negative reviews, “impressive” mostly in positive ones. Combine the clues, factor in how many reviews of each type there were, and decide.
In the test

  • Multiply and compare the two class scores
  • Read precision and recall from a confusion matrix

Text classification

  • Text classification groups text into categories (spam vs non-spam). Models learn from labelled examples.
  • Binary: two categories (spam / not spam). Multi-class: more than two (negative / neutral / positive).

Naive Bayes (no equation given in the test)

  • Uses Bayes' theorem to calculate the probability of each class and picks the most likely one.
  • Treats a document as a bag of words: order ignored, only frequency counts.
  • Naive assumption: each word is independent of the others, so a sentence's probability is the product of its word probabilities. Without it, any sentence not seen exactly in training gets probability 0.
Bayes' theorem for a class
P(class | text) = P(text | class) × P(class) / P(text)
P(text | class) = P(w₁ | class) × P(w₂ | class) × …

P(text) is the same for both classes, so ignore the denominator and compare P(class) × Π P(wᵢ | class).

Prior and Laplace (add-1) smoothing
P(class) = documents in class ÷ total documents
P(word | class) = (count of word in class + 1) ÷ (total words in class + vocabulary size)

A word that never appears in a class would give 0 and wipe out the product. Add 1 to every count, and add the vocabulary size to the denominator so the probabilities still sum to 1.

Topic 9Binary Logistic Regression

In plain English

Logistic regression gives every word a weight (positive words +, negative words −), adds them up with a bias, and squashes the total into a probability with the sigmoid.

Remember
  • Binary logistic regression predicts 0 or 1 from a feature vector x
  • Features can be word counts, word embeddings or N-grams
  • z = w·x + b; σ(z) = 1 ÷ (1 + e^−z) gives a probability from 0 to 1
  • Class 1 if σ(z) > 0.5 (same as z > 0)
  • Positive words get positive weights; negative words get negative weights
  • Naive Bayes is generative; logistic regression is discriminative
Think of it as
A judge with a scorecard: “loved” +0.28, “disappointed” −0.33. Add up the points for the words in the review plus a starting score (bias). Above 50% after squashing means positive.
In the test
  • Compute z = w·x + b from given weights
  • Apply σ(z) = 1/(1 + e^−z) and use the 0.5 threshold
  • Contrast it with Naive Bayes
  • Predicts a binary output (0 or 1) from a feature vector x = [x₁, …, xₖ].
  • Features can be word counts, word embeddings or N-grams.
  • N-grams = sequences of N consecutive items. Unigrams: "The", "quick", "brown", "fox". Bigrams: "The quick", "quick brown", "brown fox".
  • The model learns weights and a bias b. Each weight is a feature's influence: positive words like "awesome" get large positive weights, negative words like "abysmal" large negative ones.
The model
z = Σ wᵢxᵢ + b = w·x + b
σ(z) = 1 / (1 + e^−z) = 1 / (1 + e^−(w·x + b)) = P(y = 1 | x)
decision(x) = 1 if P(y = 1 | x) > 0.5, otherwise 0

The decision threshold is 0.5, which is the same as z > 0. σ(0) = 0.5.

Topic 10Convolutional Neural Network

In plain English

A CNN slides a small grid of numbers (a filter) over its input and records how well each patch matches. That makes a feature map, which pooling then shrinks.

Remember
  • A CNN has two parts: feature extraction and classification
  • Repeated operations: convolution → activation → pooling
  • Convolution: the kernel slides over the input, taking a dot product at each position, which gives a feature map
  • Filter size = receptive field; stride = step size; both are hyperparameters
  • ReLU sets negatives to 0
  • Pooling reduces the feature map size (max or average)
  • Dropout randomly disables neurons to reduce overfitting
  • Flatten → fully connected layers → output
Think of it as
Running a stencil over a page and noting how much ink shows through at each position. Pooling is then summarising each 2×2 block by its strongest (max) or average value.
In the test
  • Compute a feature map by hand (no formula given!)
  • Do max and average pooling with a given stride
  • Explain ReLU, dropout and the fully connected part
  • A deep network designed for visual data (image classification, face recognition, object detection), also used for NLP: text classification, sentiment analysis.
  • Two parts: feature extraction (convolution, activation, pooling, repeated) and classification (fully connected network).
  • Convolution: a filter (kernel) slides across the input, taking a dot product at each position. The results form a feature map (activation map).
  • Filter size sets the neuron's receptive field; stride sets how far the filter moves. Both are hyperparameters.
  • For text: the input is a sentence matrix (one row per word embedding, e.g. 7 words × d = 5). Filters span the full embedding width and cover 2, 3 or 4 words (region sizes); 1-max pooling takes the largest value per feature map; the results are concatenated and fed to softmax.

Topic 11Transformer Architecture

In plain English

A Transformer reads all words at once. With self-attention, every word looks at every other word and decides how much each one matters for understanding it.

Remember
  • The original Transformer is encoder–decoder (translation)
  • Encoder-only (BERT): classification, NER. Decoder-only (GPT): text generation. Encoder–decoder (T5, BART): translation, summarisation
  • Processes all tokens in parallel; captures long-range relationships
  • Q = XW_Q, K = XW_K, V = XW_V
  • Attention = softmax(QKᵀ ÷ √d_k) V
  • Score = query · key → softmax → weighted sum of values
Think of it as
In a group chat, to understand one message you glance back at the earlier messages that matter most. The query is your question, the keys are the message headlines, and the values are their content.
In the test
  • Match encoder, decoder and encoder–decoder to BERT, GPT and T5
  • Compute Q, K, V, the scores, softmax and the weighted sum by hand
  • Original Transformer ("Attention is all you need", Vaswani et al., 2017): encoder–decoder, built for translation.
  • Encoder: turns input tokens into contextual embedding vectors. Decoder: uses the encoder's output to generate output tokens one at a time.
  • Processes the sequence in parallel (not word by word like an RNN), so it trains efficiently on GPUs/TPUs.
TypeDoesTasksExamples
Encoder-onlyText → numerical representationText classification, NERBERT, RoBERTa, DistilBERT
Decoder-onlyPredicts the next token step by stepText generation ("The solar system has …")GPT
Encoder–decoderSequence → sequenceTranslation, summarisationBART, T5

Self-attention

  • Helps the model understand a word through its context. In "book a plane ticket", "book" attends to "plane" and "ticket", which shows it's a verb.
  • Key strength: capturing long-range relationships.
  • Maps inputs (x₁…xₙ) to outputs (y₁…yₙ). For y₃: score x₃ against x₁, x₂, x₃ with dot products → softmax → weighted sum.
Simple version (no weights)
scoreᵢ = x₃·xᵢ αᵢ = e^scoreᵢ / Σⱼ e^scoreⱼ y₃ = α₁x₁ + α₂x₂ + α₃x₃
With query, key and value
Q = X·W_Q K = X·W_K V = X·W_V
Attention(Q, K, V) = softmax( QKᵀ / √d_k ) V

Query = the current token asking. Key = what each token is compared against. Value = what gets mixed into the output. √d_k (key dimension) keeps the dot products from getting too large.
